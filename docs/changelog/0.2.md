# 0.2.x

`@standhigher/bshopify` 的 0.2 系列变更。只记录功能或行为变化；纯文档发布不列入。

## 0.2.0 - 2026-09-24

### Added

- `bshopify config autoupgrade on|off|status` 与 `bshopify upgrade`。自动升级默认开启：每条命令结束后在后台检查 npm 最新版本，落后且距上次自动升级超过 24 小时时，以 detached + unref 的子进程后台执行包管理器安装（`stdio` 忽略），绝不阻塞命令或 CLI 退出。`CI`、非 TTY、`--help`/`--version`、`config`/`upgrade` 自身会跳过；`bshopify config autoupgrade off` 关闭，`bshopify upgrade` 手动升级（阻塞、`stdio` 继承）。

### Fixed

- `app dev` / `app deploy` 中断时对 `shopify` 子进程做信号升级兜底：先转发优雅信号，`BSHOPIFY_KILL_GRACE_MS`（默认 5 秒）后仍不退出则 SIGKILL 直接子进程，确保注入值一定还原。子进程保持在 bshopify 的前台进程组（不 detach），保留 `shopify app dev` 的交互式 stdin（`q` 退出等）。修复 Shopify CLI 自动升级阻塞其 postrun 导致 dev 退出后进程卡住、注入值无法还原的问题。
- `app dev` / `app deploy` 启动时扫描 `extensionsRoot`，从工作区直接还原上次异常中断残留的 `bshopify-restore:` marker 注入（不依赖 transaction journal；marker 自描述，含占位符、值、校验和，单文件即可还原）。扫描仅限 marker 支持的文本扩展名，跳过 `node_modules`、`dist`，以及相邻有 `Cargo.toml` 的 Rust `target` 构建产物。
- `app dev` / `app deploy` 退出还原时，单个文件缺失（ENOENT）会跳过并继续还原其余文件，不再中断整个还原流程；切分支后残留注入或缺失文件也能完整还原。
- 启动时清理无 stale lock 残留的孤儿 transaction journal，避免历史中断留下的空 journal 堆积。
